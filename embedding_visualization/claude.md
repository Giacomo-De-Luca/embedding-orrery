# CLAUDE.md - Embedding Visualization Frontend

Next.js 16 web app for visualizing embedding collections with interactive 2D/3D scatter plots and semantic search. Supports flexible metadata with automatic field detection.

## Development

```bash
npm run dev                    # Frontend only (http://localhost:3000)
npx shadcn@latest add [name]  # Add UI components
```

## Build & bundler (Next.js 16)

Next.js 16 makes **Turbopack the default** for `next dev` and `next build`. Two build scripts use **different bundlers on purpose**:

- `npm run build` → `next build --turbopack` — local/default build.
- `npm run build:docker` → `next build --webpack` — Docker/production image. Opts back into **Webpack** because the `webpack()` function in `next.config.ts` is still needed there, and Next 16 **fails** a Turbopack build when a `webpack` config is present unless a bundler flag is passed. Also sets `ORRERY_DOCKER_BUILD=1` (flips `typescript.ignoreBuildErrors`).

**Forked-Plotly aliases — Turbopack ignores the `webpack()` function, so both must be declared in `turbopack.resolveAlias` too:**
- **glslify** → `./glslify-runtime-stub.js` (the SAME runtime stub webpack uses). Must be the runtime stub, **not** an empty module / `false` — the regl-* packages call `glslify()` at runtime around their pre-compiled shaders, so an empty module makes `createScatter()` throw (react-plotly swallows it) and **2D scattergl renders blank**. See the troubleshooting note below.
- **maplibre-gl.css** → `./maplibre-css-stub.js` (empty JS module). `forked/plotly.js/src/registry.js` `require()`s this CSS for unused map traces; Turbopack **cannot instantiate a CSS module required from JS** ("module factory is not available"), which aborts the entire Plotly load. Aliasing CSS→CSS does not work — the target must be a JS module. Webpack imports the real CSS fine, so it's Turbopack-only.

**Slim Plotly entry**: `forked/plotly.js/lib/index.js` registers only `scattergl` and `scatter3d` (core adds `scatter`), not upstream's ~48 traces, the two map libraries or calendars (−59% Plotly JS). **A new Plotly trace type must be registered there**: plotly drops an unregistered type silently, leaving an empty plot. `forked/__tests__/plotlyEntry.test.ts` fails until it is, provided the type is written as a string literal in a `type:` value. See `forked/plotly_changes.md` change 5.

`reactCompiler` is a top-level option (promoted out of `experimental` in Next 16); it relies on Babel, which makes the Webpack `build:docker` much slower, so it is set to `!isDockerBuild` (on for dev/Turbopack, off for Docker).

**HF Space builder OOM (exit 137)**: the build VM kills the whole job when webpack's compile peak overlaps the backend stages BuildKit runs in parallel (venv copy, model bake, seed download) — a build with the identical toolchain passes or dies depending on which layers are cache-warm. Three-part mitigation: the root `Dockerfile` **serializes the stage graph** (backend-deps → runner-base → frontend-builder → runner, via a marker `COPY --from=runner-base`) so peaks never stack; `experimental.webpackMemoryOptimizations` is on for Docker builds (string interning — significant with the forked-plotly's huge modules); and `NODE_OPTIONS=--max-old-space-size=3072` caps V8 *below* the container limit (Node sizes the default from the builder host's physical RAM, which overshoots) so webpack GCs under pressure. If the build ever fails with a *visible* JS heap-out-of-memory error, that cap is the knob to raise.

Six pre-existing broken/abandoned files (unimported, importing uninstalled `@uwdata/mosaic-*` etc.) are in `tsconfig.json` `exclude` so `next build`'s whole-program type-check passes — delete them as follow-up.

## Component Architecture

```
page.tsx (orchestration)
  ├─ AppHeader (grid: panel toggles, semantic search, collection selector, actions; HeaderMenu below xl)
  ├─ DashboardPanel (resizable layout via react-resizable-panels)
  │   ├─ ScatterPlot2D (Plotly WebGL)
  │   ├─ ScatterPlot3D (Plotly 3D with spherical camera interpolation)
  │   ├─ Legend (category colors, gradient legend, click-to-mute)
  │   └─ SimilarItemsTable (semantic search results, @tanstack/react-table)
  └─ EmbeddingSidebar (controls + selected point info + text search)
```

Shared `useEmbedDataset` hook for GraphQL operations (fires sonner toasts on embed/topic completion and failure — `<Toaster/>` is mounted app-wide in `app/providers.tsx`). **Jobs & progress**: a page-global `ActiveJobsStrip` (polls `GET_EMBEDDING_JOBS` every 5s via `useEmbeddingJobs`, all statuses) lists running + interrupted jobs on every tab — so jobs stay visible after a reload — with Resume (shared `resumeJob()` dispatcher in `embeddingFormUtils.ts`, keyed on `jobType`), Cancel (embedding and `llm_labeling` jobs, via `useCancelJob`) and Remove. Client-initiated embeds/LLM-labeling show the centered blocking `ProgressModal` (a bottom-right `JobProgressDock` was tried and reverted — user judged it a downgrade: off-center, cramped at 420px); jobs whose progress is on screen are hidden from the strip via `hideJobIds`. Image/vector file embeds (`activeJobCancellable` false), topic extraction/reduction/evaluation and SaeTab's `prepareSaeData` modals are not cancellable. See `documentation/JOB_CANCELLATION.md`. `JobsPanel`/`EmbedProgressSection` were deleted (absorbed into the strip/modal wiring in `page.tsx`). **Manage tab** is a master–detail layout: searchable `manage/CollectionListPane` (name + item/provider/topics badges; pure `filterCollections` in `lib/collectionFilter.ts`) and `manage/CollectionDetailPane` (header with Quick Action links via `buttonVariants` + `DeleteCollectionDialog` AlertDialog, preview table with click-to-expand `PreviewCell` popovers, metadata editor, SAE sections, TopicExtractionCard). **Embed flow**: numbered section cards ("1 · Data Source" … "5 · Embedding Model"), scroll-into-view on info load, and a sticky `EmbedFooterBar` (config recap from `buildEmbedSummary` + primary CTA + first blocking issue from `getEmbedValidationIssues`, both pure in `lib/embedValidation.ts` — no more `alert()`s). HF/Local share `useEmbedFormState` (columns/template/portion/model state, per-tab instances) and pure input builders (`buildHFEmbedInput`/`buildLocalEmbedInput`/`buildReEmbedInput` in `embeddingFormUtils.ts`, unit-tested); the two tabs keep intentionally distinct UIs. `PortionSelector` takes `allowedStrategies` (LocalFileTab omits `ROW_RANGE` — `EmbedLocalFileInput` has no range fields; previously shown-but-inert). TopicExtractionCard is a thin shell over `topics/TopicListSection` (rename/regenerate), `topics/ReduceTopicsSection`, `topics/LlmLabelingSection`, and `topics/TopicQualitySection`. **Post-embed SAE step** (`SaeActivationsSection` + `parseSaeSelection`/`runPostEmbedSaeStep` in `embeddingFormUtils.ts`, unit-tested): optional card rendered after each topics section (HF, Local embed, Local re-embed; not SaeTab) — checkbox + SAE model select (same `modelId::saeId` composite as the manage tab's SaeLinkSection; state on `useEmbeddingModelState` via `getSaePostParams()`). After the embed mutation resolves successfully, the tab handler links the collection (`updateCollectionMetadata` writes `sae_model_id`/`sae_id` — the backend reads the SAE to run from collection metadata, so link must precede compute) then runs `computeDocumentActivations`; a failed link skips the compute, a compute error surfaces via the shared error state without failing the embed. The activations ProgressModal is **page-global** in `page.tsx` (driven by `activeDocActivationsCollection` + `docActivationsLoading` from `useEmbedDataset`) so it covers both embed-flow and manage-pane runs; the manage pane's SAE Document Activations card sits **after** TopicExtractionCard (optional final step) with an "Already computed" badge from `hasDocumentActivations`. **TopicQualitySection**: score the current topics via the `evaluateTopics` mutation (self-contained `lib/hooks/useTopicQuality.ts`, mutation-promise completion + `{collection}_evaluate` ProgressModal). Metric picker = `ToggleGroup type="multiple"` pills (Silhouette/Diversity/C_v (slow)/U_Mass; DBCV pill permanently disabled — needs the live fitted model), topic/subtopic level toggle when `hasSubtopics`. Results render as monospace badges per level with a multi-line native-`title` interpretation tooltip (pure helpers in `lib/utils/topicQualityFormat.ts`, unit-tested); persisted scores arrive via `collectionTopics.qualityMetrics` (keyed `{topic, subtopic}`, requested by GET_COLLECTION_TOPICS into `lastTopicsResult`), and fresh runs override per level (a fresh run REPLACES that level's stored blob server-side — unselected metrics drop from the badges). The jobs strip renders **below** the tab content, and jobs whose progress is already on screen (progress modal) are excluded via `hideJobIds`. Because the Card primitive is intentionally surface-less app-wide (glassy Explore overlays), the collections page root scopes a card surface for dark-mode hierarchy: `**:data-[slot=card]:bg-card/60` + soft border (`page.tsx`). **TopicConfigForm** (`app/collections/components/TopicConfigForm.tsx`, shared by TopicExtractionCard, SaeTab, and the embed-with-topics flow): exposes one merged **"Clustering Space" select** instead of separate Projection Type / Clustering Space controls (the projection toggle was ignored whenever a raw-vector mode was active). State field `clusteringSpace` holds either a stored projection (`umap_3d` default, `umap_2d`, `pca_3d`, `pca_2d` → sent as `clusterOn:"projection"` + that `projectionType`) or a raw-vector mode (`cluster_umap`/`embedding` → sent as `clusterOn`, with `projectionType` pinned to `umap_3d` for the backend's id/document load + fallback). `toTopicConfigInput` does the split back to the GraphQL pair.

## State Management

Visualization state is managed by a **Zustand store** (`lib/stores/useVisualizationStore.ts`) with `subscribeWithSelector` middleware. Components read state via selectors for granular re-renders — no prop drilling of visualization state.

- **Store shape**: `VisualizationStoreState` defines all fields; `VisualizationStoreActions` defines mutations
- **ColorScale union** (`lib/types/types.ts`): Discriminated union `{ type: 'categorical' } | { type: 'sequential'; scaleName } | { type: 'diverging'; scaleName } | { type: 'monochrome'; baseColor }`. Replaces the old flat fields (`colorScaleType`, `sequentialScaleName`, `divergingScaleName`, `monochromeColor`). `categoricalPalette` stays separate — chart components need it regardless of scale type.
- **Auto-reset subscription**: Store subscribes to `colorByField` changes and auto-clears `mutedCategories` + `hideUnclustered` (synchronous, no React effect needed)
- **Persisted preferences**: the store composes `persist` inside `subscribeWithSelector` with a `partialize` whitelist — `method`, `mode`, `nebulaMode`, `showClusterLabels`, `showAllClusterLabels`, `showAxes`, `pointOpacity`, `distanceMetric` survive reloads via localStorage key `viz-preferences`. Collection-scoped state (colorByField/colorScale/mutes/temporalRange/tooltipFields/…) is deliberately excluded — it keeps its URL-param / per-collection-default / `resetForCollectionChange` lifecycle. `skipHydration: true` + the `StoreHydrator` effect in `app/providers.tsx` rehydrate post-mount so SSR HTML and the first client render agree (no hydration mismatch; defaults flash for one frame).
- **Self-contained controls**: `ColorScaleSelector` and `VisualizationControls` read/write the store directly with zero props for state (`VisualizationControls` receives only two derived gating booleans, `hasActiveFilter`/`hasHighlights`, from DashboardPanel — topic-selection muting and highlight counts aren't in the store)
- **Data stays as props**: Points, search results, topics, and other computed data flow via props (not the store) since they come from GraphQL/hooks

## Troubleshooting

- **Plotly types**: Use type assertions (`as Partial<Config>`)
- **Color scale not loading / custom strip shows as viridis**: Crameri/strip colormaps (e.g. `hilbertColor`) are lazy-loaded JSON chunks read synchronously from cache via `getCrameriPlotlyScale()`; an unloaded strip falls back to viridis. The scatter plots call `useColorScaleReady(colorScale)` (`lib/hooks/useColorScaleReady.ts`) to lazy-load **the active** strip and bump a tick that forces the colorscale `useMemo` to recompute when it lands — needed because a scale set programmatically (URL param / collection default) never opens `ColorScaleSelector` (which is the only other thing that triggers the load). Include that tick in any new colorscale memo deps.
- **Categories all gray**: Check `buildCategoryColorMap()` — presets only override specific values
- **A tour step is silently skipped after adding a `prepare` to it**: react-joyride polls for a not-yet-mounted target ONLY on steps with no `before` hook (`useLifecycleEffect` effect 2 — the polling branch is `else if (!beforeRef.current)`). Adding a prepare opts the step out of that polling: it goes straight to READY, a missing target counts as TARGET_NOT_FOUND, and joyride advances to the next step. Any prepare on a step whose anchor mounts late (behind a collection load, or inside a panel that's sliding in) must own the wait itself — `waitForAnchor(selector, timeoutMs)` in `tourSteps.ts`. This is what turned the Explore tour's first step into "the tour opens on step 2".
- **Sidebar/ScrollArea content flush against the right edge (right padding clipped)**: Radix ScrollArea wraps viewport children in a `display: table; min-width: 100%` div, which grows *past* the viewport when any child has a large intrinsic width (a measured recharts svg, nowrap `truncate` labels) — the overflow is clipped (`overflow-x: hidden`), swallowing the content's right padding. Since the recharts svg re-measures against the wider wrapper, the state is self-sustaining. Fix: force the wrapper to block with `[&>[data-radix-scroll-area-viewport]>div]:block!` on the ScrollArea — applied in the `SidebarContent` primitive (`lib/ui-primitives/sidebar.tsx`) and CategoryBarList's inner list. Only do this where horizontal scrolling is never wanted (tables that scroll horizontally need the table wrapper).
- **`scene.scatter2d.update is not a function` / 2D scattergl renders nothing (3D fine)**: two related causes. (1) plotly marks regl components with the placeholder `true` during the calc pass (`calc.js`) and only creates the real objects in the dirty plot call (`plot.js`); a pan/zoom drag or box-select landing in that window called `.update()` on the boolean. Patched in the fork (`forked/plotly.js/src/traces/scattergl/scene_update.js`, `select.js`, `edit_style.js`) with `isReady()` guards. (2) The regl-* packages call `glslify()` **at runtime** around their pre-compiled shader strings, so `next.config.ts` must NOT alias glslify to `false` — that makes `createScatter()` throw (silently swallowed by react-plotly, which has no `onError`), leaving `scene.scatter2d` stuck on the placeholder → blank plot. The alias points to `glslify-runtime-stub.js` (tagged-template join) instead. **Under Next 16 this alias must ALSO be declared in `turbopack.resolveAlias` (Turbopack ignores the `webpack()` function) — see "Build & bundler".** Note the breakage only surfaces after a clean `.next` rebuild — stale webpack-cached chunks can mask config-level regressions for a long time. Also: never run two `next dev` instances against the same `.next` (corrupts chunks → ENOENT / 404s / silent server death).
